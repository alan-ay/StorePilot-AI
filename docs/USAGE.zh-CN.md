# StorePilot 操作说明

## 启动

在项目根目录安装依赖后运行 `streamlit run app.py`。第一次打开时使用演示数据，
顶部与侧栏会明确标出。演示数据用于了解界面，不能用来证明真实门店的预测效果。

## 每天怎样用

1. 单家门店会自动选中。首页查看最近营业额、优先补货商品、待审核金额和需要复核的库存。
2. 打开“补货清单”。按商品名或编号搜索，也可以筛选品类、待处理或已处理项目。
3. 选中商品，核对现货、在途、预计日销量、交货时间与建议数量。
4. 选择“按建议补货”“调整数量”或“本次不采购”。调整与不采购时填写原因。
   点击“保存安排”后，记录会保存到本地，采购草稿同步更新。
5. 打开“采购与记录”。按门店和供应商核对草稿，勾选确认后点击“审核本单”。
6. 在“处理记录”下载已审核订货清单，自行联系供应商。软件不会发送订单或付款。

每箱数量与起订量会同时校验。比如每箱 6 件、最低起订 10 件，实际至少应订 12 件。
选择不采购时，确认数量会归零。超出本批次合计预算时，采购审核会被阻止。

已审核的单据会固定保存，同一批次重复点击不会再生成一单。导入新数据或者更改
备货策略会建立新批次，旧记录仍在“历史批次采购”中。审核新批次之前请先核对已订货，
防止重复购买；已审核并不代表供应商已经收单，也不会自动增加在途数量。

## 测算经营变化

“情景测算”用于比较自行输入的假设。可以设置涨降价、促销需求、客流、节假日与
额外交货延迟。价格弹性也是假设，并未通过你的门店数据估计。同一活动造成的客流与
促销提升不要重复计入。测算不会改写补货清单、采购草稿或审核记录。

## 看趋势与调拨

“销售走势”把最近实际销量和未来需求放在同一张图里，并显示参考误差范围。
演示数据已合并为一家门店 `STORE-01`，原两家门店的销量、销售额和库存总量均保留。
只有导入多家门店的数据后才会显示“门店调拨”；调拨只列出现货可用的调配机会，
不会把还在路上的货当作可调货物。
调拨的货值不是净节省金额，还需要核对运输费用、到达时间和商品批次。
安排调拨后，请更新库存或调整采购草稿，避免既调货又采购。

## 导入门店数据

在“数据与设置 → 导入数据”上传 `sales.csv`、`products.csv` 与 `inventory.csv`，
点击“检查并使用这组数据”。可以先下载演示文件查看格式。

- 每天、每个门店、每个商品只能有一条销售记录。
- 建议准备至少 70 天历史；所有商品记录应更新至同一截止日期，零销量日也保留。
- 价格、成本、销量和库存需是完整的有限数值；不接受负值、无穷大或非法整箱数量。
- 三份文件合计最多 25 MB。无历史销量的库存商品会在数据说明中提示，暂不给建议。
- 导入失败时继续保留当前数据，不会一半导入、一半沿用旧文件。

导入的三份文件仅在当前页面会话中使用，重新启动后需要再次导入。采购与处理记录
保存在本地 SQLite 数据库中，演示与门店数据使用不同数据库。备份时请一并保存数据库。

## 需要由店主核对的内容

当前没有批次到期日，所以“核对保质期”仅表示库存可能偏多；没有预计到货日，所以
在途货物何时可卖仍需向供应商确认。店主反馈会保存供复盘，当前不会自动改变模型。
每次导入新销量时会重新拟合预测。页面筛选与情景调整不重复训练。
